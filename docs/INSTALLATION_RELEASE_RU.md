# Установка и выпуск ARC Live

## Что получает пользователь

- один файл `ARC-Live-Setup-<version>.exe`;
- одно подтверждение UAC во время установки;
- обычный запуск ARC Live без прав администратора;
- фоновый `ARC Live Capture Service`, который запускает WinDivert только когда
  открыт пользовательский интерфейс;
- автоматический запуск в фоне при входе в Windows и управление через трей;
- сохранение истории, настроек и `widget-config.json` при repair, upgrade и
  удалении программы;
- предпочтительный адрес OBS `http://127.0.0.1:17842/overlay/live`; при конфликте
  ARC Live выбирает свободный loopback-порт, сохраняет и показывает новый URL.

При повторном запуске уже открытая, в том числе скрытая, копия ARC Live
показывает существующее окно. Второй экземпляр не запускается.

## Архитектура прав

`arc-live.exe` работает от обычного пользователя. Сервис
`ArcLiveCapture` устанавливается под `LocalSystem`, потому что обычный процесс
получает `ERROR_ACCESS_DENIED` при `WinDivertOpen`. GUI и сервис общаются только
через loopback. Подключение подтверждается 256-битным случайным токеном из
пользовательской папки данных. Сервис принимает только фиксированный
`arc-live-tls.keys` внутри дерева данных ARC Live.

Bearer-токен игры не извлекается. TLS-ключи не возвращаются из сервиса. Сервис
пассивно читает штатный ответ статистики игры при возвращении в Сперанцу; GUI
получает нормализованные счётчики и безопасную JSON-схему ответа.

## Сборка development-установщика

```powershell
.\scripts\build-installer.ps1 -UnsignedDevelopmentBuild
```

Скрипт создаёт:

- `dist\ARC-Live-Setup-<version>.exe` — основной Burn bootstrapper;
- `dist\ARC-Live-<version>-x64.msi` — MSI для администрирования/Store;
- `dist\ARC-Live-Portable-<version>-windows-x64.zip` — portable-вариант;
- `dist\stable.json` — манифест обновления;
- `dist\winget\*.yaml` — манифесты Windows Package Manager.

Требуется WiX 5.0.2 и расширение `WixToolset.Bal.wixext/5.0.2`. WiX 5 выбран
осознанно: начиная с WiX 6 бинарные сборки поставляются с дополнительными
условиями OSMF, которые нельзя принимать от имени владельца проекта
автоматически.

## Публичный выпуск через GitHub

Исходный код, CI и выпуски находятся в
[`sokol-rc/ArcTwitchWidget`](https://github.com/sokol-rc/ArcTwitchWidget).
Обычный выпуск создаётся тегом, версия которого совпадает с `workspace.package.version`:

```powershell
git tag v0.10.3
git push origin v0.10.3
```

Workflow `Release` на чистой Windows-машине собирает EXE, MSI и portable ZIP,
создаёт манифест, подписывает его релизным Ed25519-ключом и прикрепляет все
файлы к GitHub Release. Закрытый ключ хранится только в GitHub Actions secret
`ARC_LIVE_UPDATE_SIGNING_KEY`; его нельзя помещать в репозиторий, логи или
артефакты сборки.

Тег вида `v0.10.3` публикует стабильный выпуск. Тег с суффиксом, например
`v0.11.0-beta.1`, публикует prerelease и обновляет машинный указатель канала
`beta`.

Сертификат Authenticode не является частью репозитория. Пока коммерческий
сертификат не куплен, Windows SmartScreen может показать предупреждение о
неизвестном издателе. Внутренняя проверка обновления от этого не зависит:
ARC Live доверяет только манифесту с корректной Ed25519-подписью и установщику
с указанным в нём SHA-256. Позже Authenticode можно добавить вторым уровнем
доверия через `ARC_LIVE_SIGNING_CERT_SHA1` и `ARC_LIVE_TIMESTAMP_URL`.

## Обновления

ARC Live поддерживает каналы `stable` и `beta` с постоянными адресами:

- `https://github.com/sokol-rc/ArcTwitchWidget/releases/latest/download/stable.json`;
- `https://github.com/sokol-rc/ArcTwitchWidget/releases/download/beta/beta.json`.

Манифест представляет собой подписанный конверт: внутри находятся версия,
канал, неизменяемый URL установщика, размер и SHA-256. Приложение сначала
проверяет встроенным публичным ключом Ed25519 весь payload, затем размер и хеш
скачанного файла. Изменить URL или хеш без закрытого ключа невозможно.
Обновление нельзя запустить, пока обнаружен процесс игры.

Релиз 0.10.3 отозван. Следующий установщик публикуется после живого теста
динамического региона и событийного обновления при возвращении в Сперанцу.
После нового стабильного релиза приложение снова сможет находить последующие
обновления автоматически.

Burn/MSI выполняет major upgrade транзакционно: сервис останавливается,
файлы заменяются, затем сервис запускается снова. База, логи, конфигурация и
история лежат в `%LOCALAPPDATA%` и не входят в MSI, поэтому upgrade/repair их не
затрагивает.

## Проверка перед выпуском

1. Чистая установка одним Setup.exe и один UAC.
2. Сервис `ArcLiveCapture` имеет состояние Running.
3. `arc-live.exe` запущен с обычным уровнем целостности.
4. Игра, Steam и Epic не перезапускаются.
5. Виджет OBS открывается по прежнему localhost URL.
6. Обновление с предыдущей версии сохраняет SQLite и оба JSON-конфига.
7. Repair восстанавливает EXE/DLL/SYS.
8. Uninstall удаляет программу, сервис, автозапуск и ярлыки, но сохраняет
   пользовательскую историю для возможной переустановки.
9. Установка и удаление проходят в тихом режиме с кодом 0.
10. Подписанный update-манифест отклоняет изменение payload или установщика.
11. При наличии Authenticode-сертификата все исполняемые файлы имеют подпись
    одного издателя.

Публикация в winget и Microsoft Store выполняется только после подписанного
теста. Для Store используется существующий MSI/EXE, не MSIX: текущая схема
содержит WinDivert-драйвер.
